## Context

`nb-mcp-server` uses OpenSpec 0.17.2 for spec-driven development. The workflow is defined in `openspec/AGENTS.md` (455 lines), referenced from `CLAUDE.md`/`AGENTS.md` (both symlinks to `.auxiliary/configuration/AGENTS.md`) via `@openspec/AGENTS.md`. OpenSpec 1.x (OPSX) replaces this with a skill/command model generated by `openspec init --tools opencode`.

The `nbspec` project targets OPSX for schema extensibility. This migration is a prerequisite.

## Goals / Non-Goals

- Goals:
  - Migrate `nb-mcp-server` from OpenSpec 0.17.2 to 1.x (>= 1.4.0).
  - Preserve all existing spec content and completed change archives.
  - Update agent workflow instructions to OPSX skill/command model.
  - Pin minimum OpenSpec version to avoid unstable 1.5 features.
  - Serve as pilot for eventual fleet-wide migration via agents-common Copier template.

- Non-Goals:
  - Fleet-wide migration (that belongs to agents-common Copier template).
  - Adopting 1.5 "stores" feature (explicitly unstable beta).
  - Modifying existing spec content or completed change archives.

## Decisions

- **Minimum version: >= 1.4.0.** 1.4 added case-insensitive header parsing for semantic delta sync. 1.5 stores feature is unstable beta; do not depend on it. `openspec/config.yaml` has no CLI-version field; the pin lives in project documentation (`documentation/agents/openspec.md` and a comment in `config.yaml`).
- **CLI upgrade prerequisite:** The global `openspec` CLI is 0.17.2. Upgrade to 1.x before running init. A 1.x global CLI operating on other still-0.x repos works for read/validate paths (sandbox-verified) but will offer legacy cleanup if `init` is run there — coexistence is safe but be deliberate.
- **Non-interactive init:** Run `openspec init --tools opencode` non-interactively. This detects the 0.x layout, deletes legacy `openspec/AGENTS.md` (without prompting when `--tools` is passed), creates `openspec/config.yaml`, and generates skills + commands under `.opencode/`.
- **Generated artifact policy (fleet-interim contract):** `.opencode` is an agentsmgr symlink to `.auxiliary/configuration/coders/opencode/`. OPSX-generated skills and commands are **regenerable local artifacts**, NOT vendored through agentsmgr defaults. The `.gitignore` in that directory marks `skills/` and `command/` (singular) as agentsmgr territory; OPSX 1.3+ writes `commands/` (plural), which escapes the gitignore. Resolution: add `commands/` to the coder `.gitignore`. After any `agentsmgr populate`, rerun `openspec init`/`openspec update` to regenerate. Revisit distributing a stable snapshot through agents-common only if regeneration proves brittle (tracked at agents-common:todos/template/10).
- **Instruction file edit target:** `CLAUDE.md` and `AGENTS.md` are both symlinks to `.auxiliary/configuration/AGENTS.md`. The edit is a single file change at the real path, not two separate edits.
- **New workflow documentation:** Create `documentation/agents/openspec.md` with OPSX workflow guidance (how to use skills/commands, schema resolution, change lifecycle).
- **Symlink safe:** The `openspec` symlink to `documentation/architecture/openspec` survives init intact — both 0.x and 1.x resolve it correctly.
- **No content migration needed:** Existing specs and completed changes pass `openspec validate --all` under 1.5.0 unchanged.
- **Pilot scope:** This proposal covers `nb-mcp-server` only. The durable home for the migration is the agents-common Copier template, which will propagate fleet-wide afterward. Agents Owner will review the revised proposal for the migration contract that becomes agents-common template policy.

## Risks / Trade-offs

- **Risk:** `openspec init` deletes `openspec/AGENTS.md` without prompting.
  - **Mitigation:** Commit the file before running init; the 0.x content is preserved in git history. Update `.auxiliary/configuration/AGENTS.md` in the same change to avoid broken references.
- **Risk:** 1.5 stores feature instability leaks into project config.
  - **Mitigation:** Pin minimum version to 1.4.0 in documentation; document that 1.5 stores are out of scope.
- **Risk:** Generated skills/commands clobbered by `agentsmgr populate`.
  - **Mitigation:** Treat as regenerable local artifacts; add `commands/` to coder `.gitignore`; document rerun-after-populate requirement.

## Migration Plan

1. Commit current state (preserve `openspec/AGENTS.md` in git history).
2. Upgrade global `openspec` CLI to 1.x (>= 1.4.0).
3. Run `openspec init --tools opencode` non-interactively.
4. Review generated `.opencode/commands/` and skills.
5. Review/customize `openspec/config.yaml` (init already creates it with `spec-driven` schema; add version pin comment).
6. Add `commands/` to `.auxiliary/configuration/coders/opencode/.gitignore`.
7. Update `.auxiliary/configuration/AGENTS.md` OpenSpec Instructions section for OPSX model.
8. Create `documentation/agents/openspec.md` with OPSX workflow guidance.
9. Run `openspec validate --all` to confirm existing content passes.
10. Verify symlink intact.
